# 初始化与约束

## 当前行为

`EnableTypeOrm()` 会根据业务服务的配置构造 TypeORM 连接选项。用 `DbDriver` 选择驱动，PostgreSQL 填 `postgres`，MySQL 填 `mysql`。

| 配置                                     | 含义                                                          |
| ---------------------------------------- | ------------------------------------------------------------- |
| `DbHost`、`DbPort`                       | 实例地址和实际端口。PostgreSQL 常用 `5432`，MySQL 常用 `3306` |
| `DbUsername`、`DbPassword`、`DbDatabase` | 数据库账号、密码和业务数据库名                                |
| `DbSynchronize`                          | 是否启用 TypeORM 自动同步，默认 `false`                       |

## MySQL 接入条件

1. 在业务服务安装 `mysql2` 作为运行依赖，并提供 `DbDriver=mysql` 和上表中的连接参数。
2. 创建业务数据库，用该服务支持的 MySQL 实体、迁移或初始化脚本建表。
3. 使用写请求幂等时，在同一个业务数据库执行 NestCloud 仓库的 `sql/sdk/add-rpc-idempotency-record.mysql.sql`。幂等表和参与该事务的业务表均须使用 InnoDB。 [写请求幂等接入与升级顺序](../http/写请求幂等.md)

## 实体扫描路径

当前实体扫描路径指向：

- `${process.cwd()}/dist/**/*.entity.js`

## 审计字段

继承 `BaseEntity` 的实体统一包含 `create_user`、`update_user`、`created_at`、`updated_at` 与 `deleted_at` 字段。

通过 `BaseService.create()` / `BaseService.update()` 写入时，基础服务会从 `ContextService.getCurrentAccount<T>()` 读取当前账号 id，并填充 `createUser` / `updateUser`；无请求上下文或未登录账号时跳过填充，避免启动初始化任务受影响。

若业务服务直接调用 `repository.save()`，需要在保存前复用基础服务的审计辅助方法，且当返回值需要包含数据库生成字段时，保存后应重新查询完整实体再返回。

## 使用约束

- 数据库配置必须通过 `getConfig` 与 `ConfigKey` 提供
- `synchronize` 行为变化时，应同步更新运维与部署文档
- 各服务在自身仓库维护与选用数据库匹配的业务表初始化脚本
- 若实体扫描规则、驱动或初始化方式变化，需要同步更新此处及消费方的部署说明
