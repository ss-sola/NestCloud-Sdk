# 配置加载与合并

## 本地加载

- 默认读取当前工作目录下的 `.env`
- 支持 `json`、`yaml/yml`、`env`

## 远程拉取

启用配置中心并配置 `ConfigNames` 后，启动时请求 `GET {registryUrl}/api/config-files/client/pull`，随后每 60 秒尝试刷新。每次请求复用公共远程调用的 10 秒超时，同一时刻最多执行一次刷新。

## 合并规则

- 先加载远程 `mergedConfig`
- 再合并本地 `devConfig`
- 本地开发配置最终覆盖同名远程配置
- `getConfig` 在合并结果中找不到键时，会先读取同名环境变量，再使用调用方传入的默认值。环境变量同样参与读取时的类型转换。
- 如果配置类为 `SessionSecret` 或 `SessionRedisUrl` 声明了校验装饰器，启动及刷新快照校验会在缺少该字段时读取同名环境变量。
- 合并后的配置先通过服务启动入口指定的 `validateConfig` DTO，完成类型转换、默认值填充和业务校验后才整体生效。省略的远端字段在新快照中移除，DTO 声明了默认值的字段恢复为默认值。
- 首次拉取失败或远程配置校验失败时，客户端尝试用本地配置启动。本地配置也须通过同一份 DTO 校验，缺少启动必需项时会终止启动。
- 运行中遇到网络故障、响应缺少 `mergedConfig` 对象或业务校验失败时，保留上一份已生效配置，下次轮询继续尝试。

## 类型转换

`getConfig` 会在读取时做运行时类型转换：

- 当传入默认值时，按默认值类型自动转换，例如 `getConfig<number>('Port', 3000)` 会把字符串 `'3000'` 转为数字 `3000`
- 无默认值但需要强制类型时，可传第 4 个参数：`getConfig<number>('Port', undefined, true, 'number')`
- 支持 `string`、`number`、`boolean`、`json`
- DTO 的 `@IsBoolean()` 字段按原始配置解析。布尔值、数值 `1` / `0` 和文本 `true` / `false` / `1` / `0` 均受支持，文本忽略大小写与首尾空白。其他字符串和数值会使校验失败，`.env` 中的 `BullBoardEnabled=false` 会保持关闭。
- DTO 校验成功后，后续 `getConfig<number>('Port')` 可直接拿到转换后的数字
- 转换失败会抛出配置类型错误，避免字符串继续传入底层框架

## 使用约束

- 业务代码必须通过 `getConfig` 和 `ConfigKey` 读取配置
- 配置校验优先使用 `validateConfig`
- 不允许业务代码绕过统一配置入口直接访问 `process.env`
