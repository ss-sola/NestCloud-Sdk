# 注册与发现流程

## 注册

应用监听端口前，客户端会向注册中心发起实例注册：

- `POST {registryUrl}/api/registry/register`

首次注册最多尝试 5 次，单次请求最多等待 10 秒，重试间隔 3 秒。尝试耗尽时，SDK 的启动入口记录错误并以退出码 `1` 退出进程。

`system-service`、`middleware-service` 和 `rag-service` 在 `NodeEnv=production` 时自动注册并同步实例。它们在开发环境继续使用各远程客户端声明的固定地址。其他项目可以通过 `@EnableAutoRegister()` 在所有环境开启注册，或通过 `@EnableAutoRegister({ productionOnly: true })` 仅在生产环境启用。

## 服务基础地址

| 配置项           | 用途                                          | 省略时的行为                                             |
| ---------------- | --------------------------------------------- | -------------------------------------------------------- |
| `ServiceBaseUrl` | 对调用方广播的完整 HTTP(S) 地址，可含网关前缀 | 从 `ServiceHost`、监听端口 `Port` 和 `GlobalPrefix` 组装 |
| `ServiceHost`    | 标识实例的主机名或 IP                         | 使用本机 IP                                              |
| `GlobalPrefix`   | 业务服务的 HTTP 路由前缀                      | 使用根路径                                               |

例如，配置 `ServiceBaseUrl=https://middleware.example.com/api` 后，远程方法 `/file/detail` 访问 `https://middleware.example.com/api/file/detail`。如果网关基础地址包含额外前缀或非默认端口，也应一并填入。基础地址接受域名、内网主机名和 IP，认证信息、查询参数及片段不属于该字段。

官方客户端在注册时同时发送 `host`、`port` 和 `baseUrl`。实例 ID 仍由服务名、主机和监听端口生成。多个副本可以广播相同的网关地址，但应分别使用能区分副本的主机或监听端口。

如果服务配置为 `ServiceHost=10.0.0.7`、`Port=3300`、`GlobalPrefix=api`，省略 `ServiceBaseUrl` 时会广播 `http://10.0.0.7:3300/api`。发现旧注册记录时沿用 `http://host:port`；已经存储的旧记录要包含网关或业务前缀，需由升级后的服务重新注册。切换为 HTTPS 网关前应先升级消费端，使其能识别 `baseUrl`。

## 心跳

注册成功后，客户端按固定间隔发送心跳：

- `POST {registryUrl}/api/registry/heartbeat/{instanceId}`

若发现实例不存在，会停止当前心跳并重新走注册流程。

## 本地缓存

客户端会定时同步：

- `GET {registryUrl}/api/registry/all`

首次同步在应用开始监听后执行，后续默认每 15 秒同步一次。单次请求最多等待 10 秒，同一时刻只有一个同步请求。有效响应整体替换旧快照，空列表也会清除旧实例。

快照从最后一次成功同步起最多使用 4 个同步周期，默认 60 秒。请求失败或响应无效时保留仍在有效期内的快照。尚未取得有效快照或快照已过期时，依赖服务发现的远程调用返回 `503`（服务发现暂不可用）。后台同步继续执行，收到有效快照后自动恢复。

## 使用约束

- 当注册中心地址指向当前服务自身时，客户端不会重复注册自己
- 服务发现优先读取本地缓存，不直接在业务层拼接注册中心请求
- 注册、心跳、发现接口变化时，应同步更新SDK 客户端和 NestCloud 服务端的接口说明
